# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Imperator DockFolders

macOS app (Swift/SwiftUI/AppKit) that creates custom app folder shortcuts in the Dock. Minimum macOS 14, no App Sandbox.

This app is part of the Imperator family. Visual + structural rules live in the **Imperator Apps BrandBook** at `https://gitlab.com/goranimperator/imperator-mac-apps-brandbook` — pull and read it before doing any UI work. DockFolders is already aligned: forced dark mode, brand-only red accent (`#A01818` via `AppColors.brand`, never bare `Color.accentColor`), and the standard `AppColors` / `HoverButton` / `PillIconButton` / `ViewExtensions` boilerplate is in place.

## Build, deploy, run

```bash
# Build (Release)
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project DockFolders/DockFolders.xcodeproj \
  -scheme DockFolders -configuration Release build

# Deploy + restart. Always rm -rf first — plain `cp -R` will not overwrite
# the existing bundle, so the old binary lingers in /Applications.
pkill -x "Imperator DockFolders" 2>/dev/null; sleep 1
rm -rf "/Applications/Imperator DockFolders.app"
cp -R ~/Library/Developer/Xcode/DerivedData/DockFolders-*/Build/Products/Release/"Imperator DockFolders.app" "/Applications/Imperator DockFolders.app"
open "/Applications/Imperator DockFolders.app"
```

The build phase runs `codesign --sign "Imperator Dev" --force --deep` automatically. `PRODUCT_NAME`, `CFBundleDisplayName`, the window title, and the runtime process name (set via `ProcessInfo.processInfo.setValue(...)` in `applicationWillFinishLaunching`) are all `Imperator DockFolders`. The launcher helper checks for the app by bundle identifier — if you ever rename the product or bundle id, also patch `MouseLocation/main.swift`.

There are no tests in this project. Verification is manual: build, deploy, restart, click around.

## Architecture

### File system is the source of truth

```
~/Library/Application Support/DockFolders/
  FolderName/
    .gridconfig        JSON {"columns": 3, "itemsPerPage": 9}
    .apporder          JSON ["App1.app", "App2.app", ...]
    .labels            JSON {"Slack.app": "Custom label", ...}
    Safari.app         symlink -> /Applications/Safari.app
    Slack.app          symlink -> /Applications/Slack.app
  .folderorder         JSON ["Dev", "Games", ...], the sidebar order
  .launchers/
    FolderName.app/    generated launcher bundle (custom .icns + compiled helper binary)
```

`FolderStore.reload()` rebuilds the in-memory `DockFolder` list from disk; every mutation writes through and reloads. `DockFoldersPath` enum lives inside `FolderStore.swift` and is the only place that knows about file paths or JSON shape.

### Launcher → app IPC

When the user clicks a dock folder icon, LaunchServices runs the launcher .app's
`Contents/MacOS/launch` — a copy of the compiled helper (`MouseLocation/main.swift`), NOT a shell
script. One binary does the whole chain in-process (the old bash + mousepos + pgrep + notifyutil
chain spawned four processes per click and roughly doubled click-to-popup):

1. Derives the folder name from its own bundle path (`.../<Name>.app/Contents/MacOS/launch`),
   so the identical binary is copied verbatim into every launcher bundle.
2. Captures the mouse position via `CGEvent` and writes `folder name + x + y` to
   `/tmp/dockfolders_open`.
3. App already running (`NSRunningApplication` check): posts Darwin notification
   `com.dockfolders.open` via `CFNotificationCenterPostNotification`; `AppDelegate` listens via
   `CFNotificationCenterGetDarwinNotifyCenter()` and opens the popup.
4. App not running: launches it via `NSWorkspace.openApplication` with `--background` — **no
   notification**. The app consumes the handoff file itself at launch
   (`consumePendingHandoff()`, freshness-guarded to 10s). Darwin notifications are not queued, so
   a notification posted while the app was still in dyld was silently lost and the first Dock
   click after login produced no popup; the launch-time file check is what makes the cold path
   deterministic. Do not reintroduce a notify-after-start into the helper.

If the bundle identifier `com.dockfolders.app` ever changes, update `MouseLocation/main.swift`.

The helper is compiled by the **Build mousepos Helper** build phase from `MouseLocation/main.swift`
into `Contents/MacOS/mousepos`; `LauncherGenerator.generateLauncher()` copies it into each launcher
bundle as `launch`, and `ensureMouseposHelper()` still mirrors it to `.launchers/mousepos` so
launcher bundles generated by pre-1.0.1 versions keep working until regenerated (run outside a
bundle the helper prints `x\ny` on stdout — the old script contract; keep that branch).

Launcher bundle lifecycle rules (each guards against a real, observed white-Dock-tile bug):
- Bundles are built in a **unique staging dir** and atomically swapped into place — the Dock
  re-harvests tile icons when a bundle changes on disk, and a harvest that catches a half-written
  bundle is cached as "no icon" (white generic tile). Unique staging names also make concurrent
  builds (launch-time detached task vs MainActor mutations) independent.
- The staged bundle is **validated** (launch + Info.plist + AppIcon.icns) before the swap; it is
  stamped with `DFHelperHash` (SHA-256 of the helper), so a partial build reaching the live path
  would be skipped as "current" forever.
- `updateAllLaunchersIfNeeded()` regenerates **only** bundles whose hash differs, and the caller
  restarts the Dock only when something was regenerated. Do not bring back
  regenerate-everything-at-every-launch.

Do not move the helper compile back to runtime:
`/usr/bin/swiftc` is an xcode-select shim, so on a Mac without developer tools it pops the
"Install Command Line Developer Tools" dialog at the user
(`xcode-select: note: No developer tools were found, requesting install.`).

### Dock integration

`DockController.swift` writes launcher .app bundles into `com.apple.dock`'s `persistent-apps` (not `persistent-others`) so they appear among regular apps.

**A Dock tile is tied to a folder by the file it stands for, never by its title.** A folder named after an app in the same Dock ("Safari") has that app's title too; matching titles anchored the folder's popup over Safari and let a click on Safari open the folder. `LauncherGenerator.folderName(forDockURL:)` is the one mapping: a tile is a folder's if its URL is `.launchers/<name>.app` (or, for entries from the first release, the folder directory itself). `DockIconLocator` reads the tile's `AXURL` and `DockController` parses the stored `_CFURLString`, both through that function, string work only, since the click path calls it for every tile. `addToDock` writes a real file URL (`absoluteString`, so `#`, `?`, `%` are encoded) and XML-escapes it for the `defaults` plist; escaping only spaces broke names like "Dev #1", and a raw `&` made the plist invalid so nothing was added. Direct plist read/write via `CFPreferences` + `killall Dock` to apply. URL variants with spaces and `%20` encoding are normalized when matching existing entries.

### Popup panel

`FolderPopupPanel.swift` is a custom `NSPanel` subclass (`PopupPanel`, level `.popUpMenu`, style `.borderless | .nonactivatingPanel`). The custom `PopupShape` draws the body at 18pt with a continuous curve (BrandBook 6.3/13: floating panels take the window radius; 18.25 circular is for menu bar panels only) plus an arrow 5pt tall and 12pt wide where it leaves the body. The panel is positioned over the Dock icon that `DockIconLocator` finds (Accessibility API), with the mouse position as fallback; the arrow itself is always drawn at the panel's centre, so a panel clamped against a screen edge can point beside its tile. Background is `NSVisualEffectView` with `.hudWindow` material, locked to that material per BrandBook 6.3; experiments with `.popover` / `.thinMaterial` were rejected.

- Dismissal: outside mouse-downs fed from the app-wide CGEvent tap (see Popup latency) + local Escape-key monitor. The 200ms pointer check (`checkMouseDismiss`) skips while the mouse button is down, and once a click-and-drag swipe has started (`swipeKeepsOpen`) the popup stays open until the pointer has been back inside, so a swipe released past the panel's side does not close it mid page turn. `dismiss()` drops the content view, so cells' `onDisappear` runs and a pushed cursor is popped. The event-tap fast path only counts a mouse-up as a Dock click if the button went down within 12pt of it.
- Paging: trackpad swipe, mouse wheel, page dots, and click-and-drag (ported from MenuBarFolders). An app cell is not a tap gesture: one `DragGesture(minimumDistance: 0)` decides, so a press that never travels launches the app and a swipe that started on an icon never does.
- App cell width is hard-coded to 88pt across the grid so layout stays aligned even when the "Cut app names" setting truncates names — that toggle only changes line count, never cell size. Empty placeholder cells must use the same width.
- Custom app labels always render in full (2 lines) regardless of cut mode.

### Swipe / scroll handling

Trackpad swipe navigates one page per gesture. Two implementations because event delivery differs:

- **In the popup**: `PopupPanel.scrollWheel(with:)` override. Global monitors don't fire inside non-activating panels.
- **In the main app**: `ScrollWheelOverlay` inside `AppGridCarousel`, an `NSViewRepresentable` whose `NSView` installs a local `.scrollWheel` monitor and only checks whether the pointer is over its own bounds. It used to override `scrollWheel(with:)` from behind the grid, which only ever saw scrolls in the gaps between icons: over an icon SwiftUI's own view takes the event and an unused scroll goes up the superview chain, never sideways. The view returns nil from `hitTest`, so it never takes a click.

Both feed `PageSwipeAccumulator` (in `FolderDetailView.swift`, ported from MenuBarFolders): one page per gesture. A trackpad needs a horizontal swipe and ignores momentum; a plain mouse wheel has no phases and usually no horizontal axis, so each wheel event counts as at least one detent, one detent turns a page, and a 0.25s pause ends its gesture. Routing is by gesture phase only: precise deltas without a phase (Mos, remote desktops) are treated as a wheel. Before it, a mouse wheel could never turn a page.

### Icon generation

`IconGenerator.generateIcon(for:)` renders a 1024×1024 folder icon: rounded-rect background (macOS-matching 22.37% corner radius, alpha-tuned for dark mode), subtle border stroke, and the grid of app icons inside. Writes the same icon both to the folder directory and the launcher .app bundle. `regenerateAllIcons()` reruns for every folder.

`FolderStore` triggers `IconGenerator.generateIcon(for:)` + `DockController.refreshDock()` on every mutation (`saveGridConfig`, `reorderApps`, `addApp`/`removeApp`, `renameFolder`). `applicationWillTerminate` does not have time to run icon generation, so a manual "Update Icon" button is also exposed in `GridSettingsBar` for cases where regeneration was missed.

### macOS Sequoia / Cryptex symlinks

System apps like Safari, Mail, and Maps live behind Cryptex symlinks on macOS 15+. URL-based `FileManager.contentsOfDirectory(at:includingPropertiesForKeys:)` silently skips these. `AppDiscovery.swift` uses the string-based `contentsOfDirectory(atPath:)` API instead, and `AppEntry.cachedIcon` + `AppPickerView.PickerApp.init` both call `.resolvingSymlinksInPath()` before reading the icon so Cryptex-mounted apps return the correct appearance-aware artwork. See BrandBook section 22.

### App discovery and external drives

`AppDiscovery.installedApps()` walks four fixed paths (`/Applications`, `/System/Applications`,
`~/Applications`, Xcode's bundled apps) with no depth limit, plus every mounted external volume
capped at three levels below the volume root. The cap is what makes scanning a volume safe at
all: a drive is a whole filesystem, not a curated `/Applications`.

Volumes are filtered on resource keys, and each exclusion earns its place: the root filesystem is
already covered by the fixed paths, a non-local volume would let `contentsOfDirectory` block for
as long as a network server takes to answer, and non-browsable or internal volumes are not what
"external drive" promises. `Backups.backupdb` is never descended into. `VolumeScanSettings`
(same file) holds the master switch, default on, and the per-volume exclusions, keyed by volume
NAME so the choice survives unplugging the drive.

The scan runs in a detached task from `AppPickerView`; it used to run synchronously in
`.onAppear`, which froze the sheet. `Choose Apps` in the picker is an `NSOpenPanel` and is the
answer to anything the scan cannot reach, so do not raise the depth cap to chase a stray case.

### The app has no menu bar icon, and the MenuBarExtra scene must stay

`DockFoldersApp.body` declares a `MenuBarExtra` with `isInserted: .constant(false)`. It puts
nothing in the menu bar, and it is not dead code. The app's windows are built in `AppDelegate`
rather than by a scene, so with only a `Settings` scene SwiftUI gives the app no main menu at
all: no `Settings…` item, no Cmd-comma, and `NSApp.activate` stops bringing the app forward.
Deleting that scene as cleanup breaks all three.

### Arranging the grid (iPhone / Launchpad model)

`AppGridCarousel` in `FolderDetailView.swift` is a hand-placed layout driven by a plain
`DragGesture`, not `onDrag`/`onDrop`. A system drag session floats a translucent snapshot and moves
nothing until the drop, which is what made the old grid feel broken. Holding an app (380ms) or
pressing **Arrange** starts arranging: icons wiggle, remove badges appear (only then), the held icon
lifts and follows the pointer while the others slide out of its way, and resting it at a side edge
turns the page. **Done**, Escape or a click on empty grid space ends it.

- The wiggle is a `TimelineView` (paused when not arranging), never `repeatForever`: a repeating
  animation leaks into every change in the same transaction and set the slide-into-slot wobbling.
- While arranging, reorders and removals pass `refreshDock: false`; the Dock icon is regenerated and
  the Dock restarted once, when arranging ends. Refreshing per drop ran `killall Dock`
  synchronously on the main thread: the window froze and the Dock flashed once per moved icon.
- `reorderable()` / `reorderContainer(for:)` (WWDC26) do the lift-and-placeholder natively but
  require macOS 27, and do not cover the wiggle mode, the badges or page turning. Revisit only if
  the minimum is raised to 27.

The sidebar folder list (`FolderListView`) reorders the same way: positioned rows in a
`ScrollView`, the row lifts and follows the pointer, the others slide, and one write on drop. It
was a `List` with `.onMove`, which on macOS is the same system drag session. This departs from
BrandBook 7.18 on purpose. There is no auto-scroll while dragging past the visible rows.

Rows have no hover state (BrandBook 7.5): the trash is revealed on the selected row, the row carries `.pointingHand`, and the grip is `.tertiary` at rest. Grid slots are clamped to `itemsPerPage - 1`: a page's rows can hold more slots than the page does (4 per row, 9 per page is 12 slots), and a drop in an empty one used to land on the next page.

### Multiple displays: never `NSScreen.main`

`NSScreen.main` is the screen with the key window, not the screen the Dock is on. Two rules:

- AX positions and `CGEvent` locations have their origin at the top left of the **primary**
  screen; flip them against `NSScreen.screens.first`, never `NSScreen.main`. With displays of
  different heights, the wrong flip put every Dock tile off by the difference, so the popup opened
  at the wrong height and the click tap missed tiles and fell back to the slow launcher path.
- The popup clamps and dismisses against the screen holding the clicked Dock icon
  (`FolderPopupController.currentScreen`), looked up from the icon position.

### Swift 6, main actor by default, Observation

`SWIFT_VERSION = 6.0`, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and
`SWIFT_APPROACHABLE_CONCURRENCY = YES`, the Xcode 27 template defaults: everything is
`@MainActor` unless it says otherwise, and the compiler rejects data races.

What runs off the main actor says so with `nonisolated`, and each one is there because a detached
task calls it: `DockFoldersPath`, `GridConfig`, `LauncherGenerator` (launch-time launcher refresh),
`AppDiscovery` and `VolumeScanSettings` (picker scan), `effectiveIsDark()` (icon redraw), plus the
`Shape` types SwiftUI calls off the main actor. Anything that touches `NSApp`, a window or a view
stays on the main actor. `effectiveIsDark()` answers true off the main thread instead of reading
`NSApp.effectiveAppearance` there: that read was a real data race, and the app forces dark anyway.

`FolderStore` is `@Observable`; views read it with `@Environment(FolderStore.self)`. No
`ObservableObject`, `@Published` or `@EnvironmentObject` remain.

## Inline editing pattern (double-click to rename)

Folder name in the sidebar, folder name in the detail header, and per-app label in the grid all use the same flow:

- `Text(...)` with `.onTapGesture(count: 2)` enters edit mode.
- A `TextField` is shown with `@FocusState`, `.onExitCommand`, and an `NSEvent.addLocalMonitorForEvents(matching: .leftMouseDown)` click-outside monitor installed only while editing.
- The monitor hit-tests the click against the focused field via `window.firstResponder` so clicks inside the field don't immediately resign focus.

Canonical implementation: `FolderDetailView.installClickOutsideMonitor()`. Mirror this rather than reinventing — `.background { Color.clear.onTapGesture {...} }` looks like it should work but is blocked by child interactive content.

## Code signing certificate (one-time per Mac)

The app uses a self-signed cert "Imperator Dev" — not ad-hoc — so macOS persists Accessibility (TCC) permissions across rebuilds and machine transfers. Create it once:

```bash
cat > /tmp/cert.conf <<'CONF'
[ req ]
default_bits = 2048
prompt = no
distinguished_name = dn
x509_extensions = v3_code
[ dn ]
CN = Imperator Dev
O = Imperator
[ v3_code ]
keyUsage = digitalSignature
extendedKeyUsage = codeSigning
basicConstraints = CA:false
CONF

openssl req -x509 -newkey rsa:2048 -keyout /tmp/cert-key.pem -out /tmp/cert.pem -days 3650 -nodes -config /tmp/cert.conf
openssl pkcs12 -export -out /tmp/cert.p12 -inkey /tmp/cert-key.pem -in /tmp/cert.pem -passout pass:temp123 -legacy
security import /tmp/cert.p12 -k ~/Library/Keychains/login.keychain-db -P temp123 -T /usr/bin/codesign
security add-trusted-cert -p codeSign -k ~/Library/Keychains/login.keychain-db /tmp/cert.pem
security find-identity -v -p codesigning   # should show "Imperator Dev"
```

To install on another Mac: import the `.p12`, unzip the built `.app` into `/Applications/`, `xattr -dr com.apple.quarantine` on the app (or Open Anyway in System Settings → Privacy & Security, since right-click Open no longer works), `open`, then grant Accessibility on first prompt.

## Conventions

- All UI text, documentation, and commit messages in English. Swedish is fine in conversation but never ends up in committed content.
- Never use bare `Color.accentColor` — always `AppColors.brand` (BrandBook 14.2). Same for inlined `Color(red: 0xa0/255, ...)`; route everything through the enum.
- Symlinks, not Finder aliases — created via `FileManager.createSymbolicLink`.
- `HSplitView`, not `NavigationSplitView` — needed for explicit toolbar control.
- Darwin notifications, not URL schemes — the launcher must work when the main app is not running.
- No new third-party libraries — SwiftUI + AppKit only.

## Known limitations

- Bundle identifier `com.dockfolders.app` is hard-coded in the launcher helper `MouseLocation/main.swift`.
- Dock icon cache occasionally needs a manual `killall Dock` / `lsregister` to refresh after a major change.
- App is arm64-only. `xcodebuild` builds for the host arch; a universal build needs `ARCHS="arm64 x86_64"` (the mousepos build phase already loops over `ARCHS`).

## Toolchain and SDK (macOS 27)

AppKit chooses a control's generation from the `sdk` field in `LC_BUILD_VERSION`, not from the
running macOS. An old stamp means old-looking controls forever. This is an Xcode project, so the
stamp follows the SDK Xcode builds against: Xcode 27.x gives `sdk 27.x` while `MACOSX_DEPLOYMENT_TARGET`
keeps `minos 14.0`. No manifest change is needed and the macOS 14 minimum stays, which matters
because the repo is public. Verify after any toolchain change:

```bash
otool -l "build/dd/Build/Products/Release/Imperator DockFolders.app/Contents/MacOS/Imperator DockFolders" | awk '/LC_BUILD_VERSION/,/^$/' | grep -E "minos|sdk"
```

Expect `minos 14.0` and `sdk 27.x` (`27.2` with Xcode 27.2). If `sdk` equals `minos`, the build used an old toolchain.

Toggle rules that follow from this (BrandBook 7.2):
- `.toggleStyle(.switch)`, `.scaleEffect(0.55)`, `.tint(AppColors.brand)`, `.labelsHidden()`.
- **No toggle ever gets a cursor modifier.** Switches keep the system arrow, the way System
  Settings behaves. This covers the toggle, its label and the HStack wrapping them.
- `scaleEffect` scales only the rendering; the switch still claims 54x24pt in layout. Where a
  switch shares a right edge with other controls (the Folder options rows in the sidebar), give it
  `.frame(width: 54 * 0.55, height: 24 * 0.55)` so layout matches what is drawn, then put every
  trailing control in a shared `.frame(width: trailingControlWidth, alignment: .trailing)`.
  Without that the drawn capsule sits ~12pt short of the pills and the column looks ragged.
  A left-aligned row with no shared edge (the footer `LaunchAtLoginToggle`) needs no frame.
- The old `.frame(width: 36, height: 20)` is wrong and must not come back: it is neither the
  drawn size nor the layout size.

with the `imperator-release` skill — audit first, tag and publish last, never without Goran's
explicit word. Version lives in `MARKETING_VERSION` in `project.pbxproj`; `CURRENT_PROJECT_VERSION`

that commit does not exist yet when the target stamps the number. `make release` does this;
`RELEASE_BUILD_NUMBER` in the Makefile is the value, not `BUILD_NUMBER`.

**Every release includes a README pass, before anything is tagged.** Not optional, not a
nice-to-have — Goran has called this out explicitly. Walk the README section by section against
what actually changed and verify each claim against the code: install steps, requirements,
permissions (what is asked for AND the table of what is not), the Use bullets, build commands
and build phases, the layout tree, third-party. Do the same for this file. Then report what was
stale and what was corrected. A release whose README still describes the previous version ships

## Popup latency (resolved 2026-08-15)

Click-to-popup on the dev Mac:

| Path | v1.0.0 | now |
|---|---|---|
| Warm, Accessibility granted (event-tap fast path) | ~150–170ms | **~12–19ms** |
| Warm, no Accessibility (launcher path) | ~150–170ms | **101–105ms** |
| Cold (first click after login) | 1242–1320ms, sometimes never | **375–386ms, deterministic** |

Fast path: a listen-only CGEvent tap (`setupDockClickMonitor` in `DockFoldersApp.swift`) sees the
mouse-up, `DockIconLocator.folderTile(at:matching:)` frame-matches it to a Dock tile (cached
dock-frame gate keeps non-Dock clicks to one rect test), and the popup opens without waiting for
LaunchServices. The launcher still spawns and its Darwin notification arrives ~100ms later; show()
dedups it (visible same-folder popup < 1s old). Popup dismissal for outside clicks is fed
mouse-downs by the same tap (NSEvent global monitors see neither own-app clicks nor synthetic
events); clicks inside the panel are filtered by frame in `handleGlobalMouseDown`. The toggle
guard in show() is a 0.35s window that is never consumed by the first echo — one physical click
can echo twice (tap + Darwin notification).

NSEvent global monitors do NOT see CGEventPost-synthesized events — only a CGEvent tap does.
Anything driving the app synthetically (tests) must go through the tap path.

Launcher-path fixes, in order of impact:
1. **Darwin-notification race** — the old launcher script polled `pgrep` (which sees the process
   long before the Darwin listener is registered) and then posted a notification that was
   silently dropped. Fixed by `consumePendingHandoff()` at launch + the launcher never notifying
   on cold start.
2. **Single-binary launcher** — bash + mousepos + pgrep + notifyutil (four spawns per click,
   `notifyutil` alone ~100ms wall) replaced by one compiled helper doing everything in-process.
3. **Prewarm + AX dedup** — `FolderPopupController.prewarm()` runs one SwiftUI layout pass and
   parks a ready panel at launch (~30ms off the first click); the AX dock-icon lookup result is
   passed from `openFolderPopup` into `show()` instead of being queried twice.

Remaining floor is LaunchServices spawning the launcher bundle (~50ms) + helper (~35ms) + in-app
render (~15ms). Not reducible without abandoning the Dock-tile-is-an-app model.
